# 使用说明

## 角色

初始化创建 Alice、Bob 两个合成客户、Staff 人工客服和 Operator 本地操作员。令牌只在初始化时写入明确指定的新凭据文件，数据库只保存hash。

- Alice/Bob：只访问自己的订单、会话、方案、申请和证据。
- Staff：只看未领取工单最小摘要；领取后才能读必要上下文、审核申请、结束接管。
- Operator：只处理未知模型调用的计量对账，不默认拥有客户会话或人工审核权限。

网页令牌只存在内存；退出/刷新需要重新登录。不要用真实客户信息测试。

## 客户操作

1. 登录并新建会话。例：`我要退货 ord-alice-return 1件，不想要了。`
2. 若缺订单号、问题或数量，Agent会补问；可以先要求列出订单。
3. 核对证据与待确认方案卡。卡片包含订单、商品项、数量、商品实付金额、政策条件和有效期。
4. “确认”只提交申请，不打款。拒绝不会产生申请。
5. 提交后进入人工队列；未决申请可以撤回，撤回后不可再被批准。
6. 人工结束接管后，以新消息查询结果。

自然语言“好”“同意”不会替代精确卡片确认；发送新消息会使当前未确认方案失效，需重新评估。

页面刷新与轮询只读，不重复运行模型、不重新提交申请。网络结果不明时保留原操作编号，使用原请求重试；不能为了消除报错随便换编号。

## 人工工作台

Staff登录 → 领取工单 → 阅读已授权证据 → 填写审核说明 → 记录`approved_demo`或`rejected` → 结束人工接管。

不能静默修改客户确认的商品项、数量、金额或方案类型。待审申请必须先处理或由客户撤回，才能结束接管。无申请的咨询工单可记录说明后结束。

## 未知调用与恢复

模型调用失败和“结果未知”不是同一件事。明确未发送可结束本轮；已发出但缺结果/可靠usage必须阻断。

1. 不要重启碰运气或反复发消息。
2. 在本地模型服务的实际运行记录中查明该次调用计量和结果。
3. Operator登录，选择未知call ID，填写有依据的token数和对账说明。
4. 已知token不能被改写；未知不能当0。只有实际证据支持0才可记录0。
5. 对账只保留计量并结束未知，不执行旧动作。客户另发消息再开始。

本版本对账操作接受`no_usable_result`，不支持手工注入模型响应或重放业务动作。

## TEST 与真实模型

- `--test-mode`：固定、可重复的演示策略。可检验网页、事务、人工操作和恢复，不能证明模型能力。
- `--model-url` + `--model`：真实本机结构化HTTP。请求只去显式数字loopback端点，不继承代理、不跟重定向、不自动重试或回退TEST。

未配置端点前，不要填写真实模型验收成功。无端点不影响先跑自动化，但第一项目尚不能称完整验收。

框架追踪在每次图调用中显式关闭。若启动提示旧 `LANGCHAIN_TRACING` / `LANGCHAIN_HANDLER` 配置冲突，请只为本次命令排除这两个开关，例如 `env -u LANGCHAIN_TRACING -u LANGCHAIN_HANDLER uv run after-sales serve ...`。程序不修改全局环境，不打印环境值，也不建议开启云端追踪来消除错误。
